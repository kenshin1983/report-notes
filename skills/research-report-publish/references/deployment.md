# 部署环境配置

部署目标由项目本地配置决定。首次使用前核对目标主机、用户、站点根目录、HTTP 地址，以及本机 SSH known_hosts 和密钥路径；不要把个人连接信息写入本说明。远端需有 Python 3，并已完成静态站初始化。

部署脚本从项目根目录 `deploy.local.json` 读取 host、port、user、identity_file、remote_root、base_url。该文件不进 Git，不进入公开输出。配置变更需核对用户意图与目标站点。

## 权限

新增的报告目录（含 assets）为 755，HTML/素材/JSON 为 644。脚本显式设置，不依赖本机权限或远端 umask，不使用 777，不自动 chown 或 sudo，不递归改写整个站点。

不能仅据父目录权限数字就扩大权限；应以实际 HTTP 可读性为依据。仅当实际出现 403 时排查 Nginx 用户、组和 ACL，再按用户授权修复最小路径。

## 发布顺序与保护

仅新增报告目录以及完整 reports.json。脚本默认只读计划；--apply 需要 --report 精确列出所有待新增 ID，阻止顺手发布本地其它待发布报告。

- 本地先构建 dist；元数据的 original/published 等内部字段不进入公开 JSON。
- 远端记录必须存在于本地且保持一致；脚本不做线上删除或已发布条目更新。
- 站点外临时目录暂存，核对包成员与 SHA-256，保护同名目录。
- 采用临时文件锁与 JSON 哈希比较，阻止同时发布时覆盖目录数据。
- 新报告落地并设权限后，原子替换 reports.json；有中断时已落地但未索引的相同内容可恢复。
- 最后通过 HTTP 比较远端 JSON 和新 HTML 哈希，403/404/缓存旧数据都视为未完成验证。若外部防火墙阻止站点端口，保留 SSH 验证结果并向用户说明，不擅自改防火墙。

目录文件名固定为 **reports.json**，不是 resport.json。
