# 研报分析与发布

这是用户个人研报项目的完整工作流，从目标研报项目根目录运行；默认项目为当前工作目录，也可通过 `--project` 显式指定。先读取项目 `AGENTS.md`。遵循用户当次提示词；未指定时使用项目 `prompts/研报单页HTML解读.md`，并读取 [analysis.md](references/analysis.md) 的证据与页面要求。

## 从附件到页面

1. 定位本次实际附件，核对机构、原报告日期和主题。附件不可访问时请用户重新附上，不能用文件名或旧研报代替正文。将原件无损归档至 `originals/YYYY/MM/`，不要覆盖同名但内容不同的原稿。
2. 通读正文与相关表格；扫描件需要 OCR，双栏、脚注及评级价格表应核对渲染图。重要数字在本地保留原文页码与口径核对记录，写在相邻 `analysis.md` 即可，不纳入公开输出。缺失或无法辨识的数字明确标注。
3. 创建 `reports/YYYY/机构-主题-日期/index.html` 和 `meta.json`。参考现有报告的浅色、深蓝、宋体标题设计，优先手机竖屏；自包含 HTML，必要素材放本篇 `assets/`。返回目录链接是 `../../../index.html`。无需修改任何现有报告。
4. 元数据包含 title、institution、date（YYYY-MM-DD，原报告日期）、category、region、summary、tags、published、original。核实内容后按本次生成/发布意图设置 published；草稿保持 false。标题、摘要突出真实核心主题，标签不是交互筛选功能。
5. 运行 `python3 scripts/build.py --zip`。验证页面实际可读、无横向溢出，标题/日期/数字/单位正确，公开 URL 可用，JSON 倒序且不含原稿路径。用 HTTP(S) 本机预览；不要用 file:// 加载 JSON。首页继续读取独立 reports.json，不把新数据写入 index.html，不添加搜索/筛选/统计。

## 发布模式与范围

- 用户只要求分析、草稿或生成 HTML：完成本地文件，不上传。
- 用户明确要求发布，或调用本 skill 要求完整“分析并发布”流程：在完成检查后执行下列增量部署，不重复要求对已授权发布再确认。
- 本 skill 只处理新增报告。改写已有线上报告、撤稿、修改 Nginx/父目录权限、首次整站部署不包含在新增流程内；根据用户明确请求另行处理。

服务器连接和权限配置见 [deployment.md](references/deployment.md)。凭据仅引用本地密钥路径，不复制密钥内容。主机指纹校验必须保持开启；认证或指纹错误停止并说明，不弱化 SSH 设置或反复猜账号。

从项目目录运行本 skill 的脚本（路径相对于本 SKILL.md）：

```sh
python3 /实际skill路径/scripts/deploy.py --project "/path/to/report-notes"
```

默认仅检查并输出计划，不上传。核对计划只有本次授权的报告目录和 reports.json，再执行：

```sh
python3 /实际skill路径/scripts/deploy.py --project "/path/to/report-notes" --report 2026/本次英文标识 --apply
```

多篇分别重复 `--report`。远端比本地多记录、已有元数据不一致、目录撞名或计划包含其它待发布报告时会拒绝发布；先保留数据并向用户确认处理范围，不通过删除线上内容来“修复”。

脚本先在站点外暂存，校验文件哈希，给新增公开目录设置 755、文件设置 644，先落报告后原子替换 JSON。它不上传首页、公共 assets、PDF、meta.json、提示词或分析记录，也不自动删除旧文件。若中断，先重新检查计划；完全一致的已落地目录可继续，避免重复创建或覆盖不同内容。

发布后核对脚本的 SSH 哈希与权限结果，以及 HTTP 返回的 JSON 和新 HTML 实际字节。HTTP 不可访问、403、内容不匹配时不得声称发布成功，也不要自动修改全站权限；先说明已上传和未验证部分。可在原有授权范围内重试一次，重复失败则停止。

交付简洁列出：报告主题、原报告日期、线上链接、本次上传的路径与权限检查结果。未发布时提供本地 HTML 链接及原因。原有提示词“只交付 HTML”的格式仅适用于纯生成模式，完整发布任务仍需报告发布结果。
